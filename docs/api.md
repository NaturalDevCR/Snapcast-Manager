# Snapcast Manager — HTTP API reference

This document describes every HTTP endpoint the Snapcast Manager server
exposes. It was generated by reading the real route handlers and Zod
schemas in `server/src`, not by guessing.

## Base URL and authentication

- All routes live under the `/api` mount prefix unless noted otherwise.
- Authentication is a JWT bearer token: send
  `Authorization: Bearer <token>` on every authenticated request.
- Obtain a token via `POST /api/auth/login`, or — on a first run, before
  any user exists — `POST /api/auth/setup`.
- A 401 is returned when no (or a malformed) token is presented; 403 when
  a token is presented but is invalid, expired, or belongs to a user whose
  `token_version` has been bumped by a password change or logout.
- Routes explicitly marked **PUBLIC** require no token at all. Every other
  route requires a valid JWT. Note that the `config`, `pipeSources`,
  `snapcast`, `snapclientInstances`, `snapshot`, `system`, `tools`, and
  `watchdog` routers all apply `authenticateToken` at the router level, so
  **every** route in those routers is authenticated even when the
  individual route listing below doesn't repeat it.

### Where shapes come from (Zod vs. hand-read)

This app does **not** run every request through a formal validation layer.
Only two dedicated Zod schema files exist today:
`server/src/schemas/pipeSources.ts` and
`server/src/schemas/snapclientInstances.ts`.

- Routes gated by `validate({ body/params: ...Schema })` document their
  request shape straight from that schema (marked **Zod** below). There
  are 8 of them:
  - `POST /api/pipe-sources` — `createPipeSourceBodySchema`
  - `PUT /api/pipe-sources/:id` — `updatePipeSourceBodySchema`
  - `POST /api/pipe-sources/:id/control` — `controlPipeSourceBodySchema`
  - `PUT /api/pipe-sources/:id/config` — `setPipeSourceConfigBodySchema`
  - `POST /api/pipe-sources/adopt` — `adoptPipeSourceBodySchema`
  - `POST /api/snapclient-instances` — `createSnapclientInstanceBodySchema`
  - `POST /api/snapclient-instances/alsa/:cardId` — `setAlsaVolumeBodySchema`
  - `POST /api/snapclient-instances/:id/:action` — `controlSnapclientInstanceParamsSchema` (a *params* schema)
- Every other route documents its request/response shape by reading the
  route handler's own body directly — what it destructures from
  `req.body`/`req.params`/`req.query` and what it sends via `res.json(...)`.
  These are marked **hand-read**. Most of them do light inline
  truthiness/type checks rather than formal schema validation.

When a `validate()` call rejects a request, it responds `400` with a
curated body (`shared/validation.ts`):

```json
{ "code": "VALIDATION_ERROR", "error": "Request validation failed", "issues": [{ "path": "url", "message": "..." }] }
```

General error responses (route handlers' own `res.status(...).json(...)`)
are a plain `{ "error": "<message>" }`.

Example values below are placeholders (`"<pipe-source-id>"`,
`"snapserver"`, etc.) or the real static enum values the code restricts
to — never fabricated "real-looking" values.

## Auth — `server/src/auth.ts` (mount `/api/auth`)

### `GET /api/auth/setup-status` — PUBLIC

Tells a client whether the system has been initialized (whether at least
one admin user exists).

Hand-read. Response:

```json
{ "isInitialized": false }
```

### `POST /api/auth/setup` — PUBLIC, rate-limited

Creates the initial admin user (only allowed while zero users exist).
Rate-limited per IP (10 attempts per 15-minute window; shared with
`/login` and `/change-password`).

Hand-read. Request body:

```json
{ "username": "<admin-username>", "password": "<at-least-12-chars>" }
```

Response `201`:

```json
{ "message": "Admin user created successfully", "token": "<jwt>", "user": { "id": 1, "username": "<admin-username>", "role": "admin" } }
```

Errors: `400` "System already initialized", `400` "Password must be at
least 12 characters", `400` "Username and password are required", `429`
rate-limited.

### `POST /api/auth/login` — PUBLIC, rate-limited

Logs in and returns a JWT. Rate-limited identically to `/setup`.

Hand-read. Request body:

```json
{ "username": "<username>", "password": "<password>" }
```

Response:

```json
{ "token": "<jwt>", "user": { "id": 1, "username": "<username>", "role": "admin" } }
```

Errors: `401` "Invalid credentials", `429` rate-limited.

### `POST /api/auth/sse-ticket` — AUTH

Mints a short-lived (30s), single-use SSE ticket used to authenticate
`GET /api/events` via a `?ticket=` query param (the browser `EventSource`
API can't send an `Authorization` header). Mints still require a valid
JWT.

Hand-read. No body. Response `201`:

```json
{ "ticket": "<64-char-hex>", "expiresAt": 1700000000000 }
```

### `POST /api/auth/change-password` — AUTH, rate-limited

Changes the current user's password. Bumps `token_version`, invalidating
every previously issued token, and returns a fresh one.

Hand-read. Request body:

```json
{ "currentPassword": "<old>", "newPassword": "<at-least-12-chars>" }
```

Response:

```json
{ "message": "Password updated successfully", "token": "<fresh-jwt>" }
```

Errors: `400` "Current and new passwords are required", `400` "Password
must be at least 12 characters", `401` "Current password is incorrect",
`404` "User not found", `429` rate-limited.

### `GET /api/auth/onboarding` — AUTH

Reads the current user's onboarding wizard progress.

Hand-read. Response:

```json
{ "step": 1, "dismissed": false }
```

### `PATCH /api/auth/onboarding` — AUTH

Updates onboarding progress. `step` must be an integer 0–3, `dismissed` a
boolean; either (or both) may be present.

Hand-read. Request body:

```json
{ "step": 2, "dismissed": false }
```

Response (the persisted values):

```json
{ "step": 2, "dismissed": false }
```

### `POST /api/auth/logout` — AUTH

Bumps the current user's `token_version`, invalidating all outstanding
tokens for that user (including the one used for this request).

Hand-read. No body. Response:

```json
{ "message": "Logged out successfully" }
```

## Health — `server/src/routes/health.ts` (mount `/api`)

### `GET /api/health` — PUBLIC

Fast liveness probe: answers "is the process up and can it reach its own
database". No detail.

Hand-read. Response:

```json
{ "status": "ok" }
```

On DB failure, `503`:

```json
{ "status": "error", "error": "<message>" }
```

### `GET /api/health/detail` — AUTH

Rich health report. Every check is independently try/caught — the
endpoint always returns 200 with a complete report; the caller interprets
the per-field pass/fail.

Hand-read. Response:

```json
{
  "snapserver": { "systemdActive": true, "rpcConnected": true },
  "config": { "parseable": true },
  "disk": { "freeBytes": 123456789, "freePercent": 62 },
  "permissions": { "snapshotsDirWritable": true },
  "metrics": {
    "uptimeSeconds": 3600,
    "jobsExecuted": 12,
    "errorsByEndpoint": [{ "method": "GET", "path": "/api/pipe-sources", "count": 3 }]
  }
}
```

Each field can degrade: `config` may instead be
`{ "parseable": false, "error": "<message>" }`; `disk` may be
`{ "error": "<message>" }`; `metrics.jobsExecuted` may be `null` with an
additional `jobsExecutedError` field; `metrics.errorsByEndpoint` may be an
empty array.

## Diagnostics — `server/src/routes/diagnostics.ts` (mount `/api`)

### `GET /api/diagnostics` — AUTH

Runs five self-diagnostics checks and returns only *findings* (things to
fix). A fully healthy system returns an empty `findings` array.

Hand-read. Response:

```json
{
  "findings": [
    {
      "id": "snapserver-down",
      "category": "snapserver-down",
      "severity": "error",
      "message": "Snapserver appears to be down: ...",
      "repairAction": { "label": "Restart snapserver", "kind": "endpoint", "method": "POST", "endpoint": "/api/system/service/restart/snapserver" }
    }
  ]
}
```

Categories: `unmanaged-config`, `orphaned-unit`, `fifo-no-producer`,
`snapserver-down`, `port-occupied`. Severities: `info` | `warning` |
`error`. `repairAction.kind` is `endpoint` (with `method`/`endpoint`/optional `body`) or `manual` (with `instructions`). It may be absent.

## Events — `server/src/routes/events.ts` (mount `/api/events`)

### `GET /api/events` — AUTH via `authenticateTokenOrSseTicket`

Server-Sent Events stream. Accepts **either** a normal
`Authorization: Bearer <jwt>` header **or** a single-use ticket from
`POST /api/auth/sse-ticket` passed as `?ticket=<ticket>` (the browser
`EventSource` API can't send headers). On the ticket path the connection
is IP-bound to the IP that minted the ticket.

Hand-read (SSE wire format confirmed against `shared/events.ts`). The
response is a `text/event-stream` stream of messages of the form
`event: <type>` then `data: <json>`. Four event types:

- `snapcast` — current snapserver state (`null` if never connected):

```
event: snapcast
data: {"server":{"server":{"version":"0.27.0"},"groups":[{"id":"<group-id>","name":"<group>","clients":[],"stream_id":"default","muted":false}],"streams":[{"id":"default","status":"playing","uri":{"query":{"name":"default"},"scheme":"pipe"}}]}}
```

- `service-status` — an array of monitored services (`snapserver`,
  `snapclient`, `shairport-sync`, `mpd`, `mympd`), emitted only when a
  status changed:

```
event: service-status
data: [{"service":"snapserver","status":"active"}]
```

- `job` — the current background job snapshot (see `GET
  /api/system/jobs/:id` for the full shape).
- `shutdown` — sent once just before the server closes the connection on
  graceful shutdown:

```
event: shutdown
data: {"message":"Server is shutting down"}
```

## Config — `server/src/routes/config.ts` (mount `/api/config`, ALL AUTH)

Manages `/etc/snapserver.conf` (and the modular `.base`/segment files
under `/etc/snapserver.conf.d`), plus `/etc/default/snapclient`. All
routes below require a JWT (router-level `authenticateToken`).

### `GET /api/config/server` — AUTH

Reads the raw snapserver.conf text.

Hand-read. Response:

```json
{ "content": "[server]\n#threads = -1\n..." }
```

### `POST /api/config/server` — AUTH

Overwrites snapserver.conf with the given raw text.

Hand-read. Request body:

```json
{ "content": "[server]\n#threads = -1\n..." }
```

Response:

```json
{ "message": "Server config updated" }
```

Errors: `400` "Content must be a string".

### `GET /api/config/server/parsed` — AUTH

Reads snapserver.conf and parses it into a structured object.

Hand-read. Response (`SnapServerConfig` — section → key → value; values
are `string | number | boolean | string[]`, repeated keys become arrays):

```json
{ "config": { "server": { "threads": -1 }, "stream": { "source": ["pipe:///tmp/snapfifo?name=default"] } } }
```

### `POST /api/config/server/parsed` — AUTH

Serializes a parsed config object back to text and writes it.

Hand-read. Request body:

```json
{ "config": { "server": { "threads": -1 } } }
```

Response:

```json
{ "message": "Server config updated" }
```

Errors: `400` "Config must be an object".

### `POST /api/config/save` — AUTH

Writes a config string (uses `req.body.config` directly).

Hand-read. Request body:

```json
{ "config": "[server]\n..." }
```

Response:

```json
{ "message": "Configuration saved successfully" }
```

### `GET /api/config/segments` — AUTH

Lists the modular config segment files under `/etc/snapserver.conf.d`.

Hand-read. Response (a bare array):

```json
[ { "name": "radio-sources.conf", "content": "[stream]\n..." } ]
```

### `POST /api/config/segments` — AUTH

Saves a new (or overwrites an existing) segment file, then rebuilds the
master config.

Hand-read. Request body:

```json
{ "name": "radio-sources.conf", "content": "[stream]\n..." }
```

Response:

```json
{ "message": "Segment saved successfully" }
```

Errors: `400` "Name and content are required".

### `DELETE /api/config/segments/:name` — AUTH

Deletes a segment file and rebuilds the master config. The name is
sanitized against path traversal.

Hand-read. Response:

```json
{ "message": "Segment deleted successfully" }
```

### `POST /api/config/rebuild` — AUTH

Reassembles the master `/etc/snapserver.conf` from the base file plus all
segment files.

Hand-read. No body. Response:

```json
{ "message": "Configuration rebuilt successfully" }
```

### `GET /api/config/metadata` — AUTH

Returns the static metadata describing every known config key (label,
type, default, description) per section, used to drive the config editor
UI. Served directly from `server/src/constants/defaultConfig.ts`.

Hand-read. Response:

```json
{
  "server": { "threads": { "label": "Worker Threads", "type": "number", "default": -1, "description": "..." } },
  "stream": { "codec": { "label": "Codec", "type": "select", "default": "flac", "options": ["flac", "ogg", "opus", "pcm"], "description": "..." } }
}
```

### `GET /api/config/sections` — AUTH

Returns static display configuration (label/icon/description) for each
config section.

Hand-read. Response:

```json
{
  "server": { "label": "Server", "icon": "server", "description": "General server settings like threads, user, and mDNS" },
  "stream": { "label": "Stream", "icon": "music", "description": "Audio sources, codecs, and buffer settings" }
}
```

### `GET /api/config/source-templates` — AUTH

Returns static source-type templates (pipe, librespot, airplay,
ffmpeg_radio, process, file, tcp, alsa, meta, jack) used for the guided
"add source" flow.

Hand-read. Response (array):

```json
[
  { "type": "pipe", "label": "Pipe (FIFO)", "description": "...", "uriPrefix": "pipe://", "pathPlaceholder": "/tmp/snapfifo", "params": [ { "key": "name", "label": "Name", "description": "Unique stream name", "required": true, "type": "text", "placeholder": "default" } ] }
]
```

### `POST /api/config/reset` — AUTH

Resets the base config to the built-in default and rebuilds the master.

Hand-read. No body. Response:

```json
{ "message": "Configuration reset to default" }
```

### `GET /api/config/snapclient` — AUTH

Reads `/etc/default/snapclient` (returns a default stub if the file
doesn't exist).

Hand-read. Response:

```json
{ "content": "# snapclient default options\nSNAPCLIENT_OPTS=\"\"\n" }
```

### `POST /api/config/snapclient` — AUTH

Overwrites `/etc/default/snapclient`.

Hand-read. Request body:

```json
{ "content": "# snapclient default options\nSNAPCLIENT_OPTS=\"\"\n" }
```

Response:

```json

```

## Pipe sources — `server/src/routes/pipeSources.ts`

Mounts: `/api/pipe-sources` **and** `/api/radio-pipes` (backwards-compat
alias, same router). ALL AUTH.

The `PipeSource` object (the shape returned by GET list, POST create, PUT
update, and POST adopt) is:

```json
{
  "id": "<uuid>",
  "name": "<pipe-source-name>",
  "type": "radio",
  "url": "https://example.com/stream",
  "reconnect": true,
  "reconnectStreamed": true,
  "reconnectAtEof": true,
  "reconnectDelayMax": 30,
  "idleThreshold": 15000,
  "enabled": true,
  "createdAt": "2026-08-28T00:00:00.000Z"
}
```

`type` is one of `radio` | `mpd`. The GET-list route additionally
decorates each entry with `status` (systemd state string), `fifoPath`,
and `serviceName` (`mpd` for mpd-type, else the generated
`snapcast-radio-<slug>` unit name).

### `GET /api/pipe-sources` — AUTH

Lists all pipe sources with live status.

Hand-read. Response (array):

```json
[
  { "id": "<uuid>", "name": "<pipe-source-name>", "type": "radio", "url": "https://example.com/stream", "reconnect": true, "reconnectStreamed": true, "reconnectAtEof": true, "reconnectDelayMax": 30, "idleThreshold": 15000, "enabled": true, "createdAt": "...", "status": "active", "fifoPath": "/run/snapcast-manager/snapfifo_<slug>", "serviceName": "snapcast-radio-<slug>" }
]
```

### `POST /api/pipe-sources` — AUTH — **Zod** (`createPipeSourceBodySchema`)

Creates a pipe source. `name` is required. `type` defaults to `radio`;
`url` is required when type is `radio` and must be an `http(s)://` URL
with no spaces and no `" ' ` $ \ ;` characters. Booleans/numbers are
loosely coerced: anything but literal `false` is `true`; numbers fall back
to defaults (`reconnectDelayMax` 30, `idleThreshold` 15000) on NaN/0.

Request body:

```json
{
  "name": "<pipe-source-name>",
  "type": "radio",
  "url": "https://example.com/stream",
  "reconnect": true,
  "reconnectStreamed": true,
  "reconnectAtEof": true,
  "reconnectDelayMax": 30,
  "idleThreshold": 15000,
  "enabled": true
}
```

All fields except `name` (and `url` for radio) are optional. Response:

```json
{ "id": "<uuid>", "name": "<pipe-source-name>", "type": "radio", "url": "https://example.com/stream", "reconnect": true, "reconnectStreamed": true, "reconnectAtEof": true, "reconnectDelayMax": 30, "idleThreshold": 15000, "enabled": true, "createdAt": "..." }
```

### `PUT /api/pipe-sources/:id` — AUTH — **Zod** (`updatePipeSourceBodySchema`)

Partial update. Every field is optional; `type` is strictly
`radio` | `mpd`; `url` (when present and non-empty) must pass the same
allowlist check as create.

Request body:

```json
{ "name": "<new-name>", "enabled": false }
```

Response: the updated `PipeSource`. Errors: `404` "not found".

### `DELETE /api/pipe-sources/:id` — AUTH

Deletes a pipe source, its systemd unit (radio) or mpd.conf block (mpd),
and its snapserver.conf stream entry.

Hand-read. Response:

```json
{ "ok": true }
```

### `POST /api/pipe-sources/:id/control` — AUTH — **Zod** (`controlPipeSourceBodySchema`)

Starts/stops/restarts/enables/disables a pipe's systemd unit. `action` is
strictly one of `start` | `stop` | `restart` | `enable` | `disable`.

Request body:

```json
{ "action": "start" }
```

Response:

```json
{ "ok": true }
```

### `POST /api/pipe-sources/:id/regenerate` — AUTH

Regenerates the pipe's systemd unit / mpd.conf block from its current DB
state and restarts per `enabled`.

Hand-read. No body. Response:

```json
{ "ok": true }
```

Errors: `404` "not found".

### `GET /api/pipe-sources/:id/logs` — AUTH

Returns the pipe's systemd journal logs (last 100 lines).

Hand-read. Response:

```json
{ "logs": "<journal text>" }
```

### `GET /api/pipe-sources/:id/config` — AUTH

Returns the pipe's generated systemd unit file (radio) or its mpd.conf
`audio_output` block (mpd), plus the path it was read from.

Hand-read. Response:

```json
{ "content": "[Unit]\nDescription=Radio Stream: ...\n...", "filePath": "/etc/systemd/system/snapcast-radio-<slug>.service" }
```

Errors: `404` "not found".

### `PUT /api/pipe-sources/:id/config` — AUTH — **Zod** (`setPipeSourceConfigBodySchema`)

Overwrites the pipe's raw unit-file/block content. Radio content is
validated (only `[Unit]`/`[Service]`/`[Install]` sections allowed, plus a
`systemd-analyze verify` pass).

Request body:

```json
{ "content": "[Unit]\n..." }
```

Response:

```json
{ "ok": true }
```

Errors: `404` "not found".

### `POST /api/pipe-sources/:id/config/rollback` — AUTH

Restores the previous configuration version for the pipe.

Hand-read. No body. Response:

```json
{ "ok": true, "message": "Rolled back to the previous configuration" }
```

Errors: `404` "No previous version" / "not found".

### `GET /api/pipe-sources/system/zombies` — AUTH

Counts zombie processes by parsing `/proc/<pid>/stat` (returns 0 on
non-Linux).

Hand-read. Response:

```json
{ "count": 0 }
```

### `GET /api/pipe-sources/discover` — AUTH

Scans snapserver.conf's `pipe://` sources that this app does **not** yet
track, reporting whether a matching systemd unit exists on disk.

Hand-read. Response (array):

```json
[
  {
    "name": "<pipe-source-name>",
    "fifoPath": "/run/snapcast-manager/snapfifo_<slug>",
    "sourceUri": "pipe:///run/snapcast-manager/snapfifo_<slug>?name=<slug>&codec=pcm&sampleformat=48000:16:2&idle_threshold=15000&send_silence=true&mode=create",
    "idleThreshold": 15000,
    "detectedType": "radio",
    "existingService": { "name": "snapcast-radio-<slug>", "filePath": "/etc/systemd/system/snapcast-radio-<slug>.service", "url": "https://example.com/stream", "reconnect": true, "reconnectStreamed": true, "reconnectAtEof": true, "reconnectDelayMax": 30, "isActive": true }
  }
]
```

`existingService` is `null` when no matching unit exists.

### `POST /api/pipe-sources/adopt` — AUTH — **Zod** (`adoptPipeSourceBodySchema`)

Takes an unmanaged discovered pipe source under management. Unlike
create, `url` is **not** required for radio sources (preserved behavior) —
but still allowlist-checked when present. `existingServiceName` must match
a service actually discovered on disk.

Request body:

```json
{
  "name": "<pipe-source-name>",
  "type": "radio",
  "url": "https://example.com/stream",
  "reconnect": true,
  "reconnectStreamed": true,
  "reconnectAtEof": true,
  "reconnectDelayMax": 30,
  "idleThreshold": 15000,
  "enabled": true,
  "existingServiceName": "snapcast-radio-<slug>"
}
```

Response: the adopted `PipeSource`. Errors: `400` "existingServiceName"
mismatch or slug-collision/empty-slug.

## Snapcast — `server/src/routes/snapcast.ts` (mount `/api/snapcast`, ALL AUTH)

These routes proxy JSON-RPC calls to snapserver (HTTP on `127.0.0.1:1780`
by default, via `executeSnapcastRpc`). `:id` values are snapserver group
or client ids (`"<group-id>"`, `"<client-id>"`). `executeSnapcastRpc`
resolves to the JSON-RPC response's inner `result` field only (not the
`{ id, jsonrpc, result }` envelope), so every response below carries
exactly that inner result. The exact inner shape is whatever snapserver's
JSON-RPC API returns for the given method — the examples use placeholder
values rather than an invented envelope.

### `GET /api/snapcast/status` — AUTH

Returns the current snapserver state. Serves from an in-memory cache kept
by a persistent WebSocket when available, else makes a direct
`Server.GetStatus` RPC call. Shape is the unchanged `Server.GetStatus`
result under a `status` key (confirmed in `shared/snapcast.ts`).

Hand-read. Response:

```json
{
  "status": {
    "server": {
      "server": { "version": "0.27.0" },
      "groups": [
        { "id": "<group-id>", "name": "<group>", "clients": [ { "id": "<client-id>", "host": { "ip": "<ip>", "mac": "<mac>", "name": "<hostname>", "os": "<os>" }, "config": { "name": "<client-name>", "volume": { "muted": false, "percent": 100 } }, "connected": true } ], "stream_id": "default", "muted": false }
      ],
      "streams": [ { "id": "default", "status": "playing", "uri": { "query": { "name": "default" }, "scheme": "pipe" } } ]
    }
  }
}
```

### `POST /api/snapcast/group/:id/stream` — AUTH

Sets the stream for a group (`Group.SetStream`).

Hand-read. Request body:

```json
{ "stream_id": "default" }
```

Response: the raw inner RPC result (whatever `Group.SetStream` returns):

```json
{ "id": "<group-id>", "stream_id": "default" }
```

### `POST /api/snapcast/group/:id/muted` — AUTH

Mutes/unmutes a group (`Group.SetMute`).

Hand-read. Request body:

```json
{ "muted": true }
```

Response (`result` is the inner RPC result):

```json
{ "success": true, "result": { "id": "<group-id>", "mute": true } }
```

### `POST /api/snapcast/client/:id/volume` — AUTH

Sets a client's volume (`Client.SetVolume`).

Hand-read. Request body (`volume` is an object with `percent` and
`muted`):

```json
{ "volume": { "percent": 50, "muted": false } }
```

Response (`result` is the inner RPC result):

```json
{ "success": true, "result": { "id": "<client-id>", "muted": false, "percent": 50 } }
```

### `POST /api/snapcast/client/:id/name` — AUTH

Renames a client (`Client.SetName`).

Hand-read. Request body:

```json
{ "name": "<new-client-name>" }
```

Response (`result` is the inner RPC result):

```json
{ "success": true, "result": { "id": "<client-id>", "name": "<new-client-name>" } }
```

### `POST /api/snapcast/group/:id/name` — AUTH

Renames a group (`Group.SetName`).

Hand-read. Request body:

Disconnects a specific socket (peer IP/port), typically to kill a
